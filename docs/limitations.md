# Ограничения учебной реализации

* Это исходный код для изучения, не развернутый корпоративный продукт. Нет
  доступа к реальным сервисам, заказам, GPU кластеру или измеренным метрикам.
* Зависимости не устанавливались, модели не скачивались, training/pytest/Docker/
  Kafka/ES/Redis/ONNX inference/CI/CD не запускались. Синтаксис не доказывает API
  compatibility, корректность CUDA, latency или достаточность resource limits.
* Корпоративного Order API нет: есть typed client, OpenAPI контракт и явно
  ограниченный mock. Identity/RBAC/mTLS/redaction остаются внешними предпосылками.
* Консервативные deterministic router guards закрывают показанные неоднозначные
  сценарии, но естественный язык сложнее regex. Нужны экспертные данные,
  adversarial evaluation и UI с явным выбором билета.
* General action и необходимость выбора всё ещё зависят от вероятностного
  router. Backend усиливает проверки, но не становится полноценным NLU парсером.
* Для разных вертикалей запрашивается уточнение. Раздельная параллельная
  генерация нескольких секций со своими источниками пока не реализована.
* Числовая проверка требует наличия тех же атомов в cited evidence, а даты ISO
  дополнительно сверяются с departure_date. Это консервативно и может отклонять
  даты общих правил. Наличие числа не доказывает связь с нужным тарифом или
  единицами измерения. Суммы не вычисляются; нужен типизированный facts engine.
* Статусы заказа в текстовых claims запрещены целиком. Даже если такой статус
  был в Order API, утверждение о нём отправляется на ручную проверку. Это
  безопаснее вероятностного подтверждения, но ограничивает полезные ответы.
* NLI может ошибаться, особенно на отрицаниях и числах. Lexical splitting claims
  не является полноценным русским sentence parser; длинные premises обрезаются.
* Prompt injection из документов нельзя полностью устранить инструкцией промпта.
  Public KB ingestion должен быть доступен только доверенным редакторам.
* Ingestion имеет at-least-once семантику и окно видимости разных версий. Есть
  retry/DLQ, но нет UI replay, удаления документа, полноценного ETL scheduler,
  distributed lock для независимых writers и atomic alias rebuild.
* Redis invalidation — TTL плюс ручная смена KB_VERSION; изменения в ES не
  гарантируют мгновенный сброс общего кэша. Кэш нужен только для узкого каталога.
* Есть sample cases и unit tests, но нет тестов внешних API/ресурсов, end-to-end
  benchmark, нагрузочного теста и измеренных baseline/LoRA результатов.
* ONNX export зависит от поддержки checkpoint/ops. Tokenizer и label semantics
  сохранены, численная parity Transformers/ONNX не проверена.
* Kubernetes манифесты предполагают внешние ES/Kafka/Redis/DNS/storage и device
  plugin. Default Secret и registry placeholders нужно заменить. JSON форма
  Deployment файлов валидна как YAML 1.2, но cluster schema/admission не проверялись.
* vLLM/TRL/RAGAS API targets заданы явно, другие зависимости имеют диапазоны.
  Lockfile и полная воспроизводимость окружения требуют отдельного разрешения.
* CI security tools могут находить проблемы в выбранных зависимостях. Эти
  проверки включены, но их прохождение не заявляется.
