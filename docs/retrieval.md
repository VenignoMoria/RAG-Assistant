# Retrieval: от запроса к источникам

`HybridRetriever.search` нормализует пробелы, затем получает E5 embedding.
`intfloat/multilingual-e5-large` использует **query:** для запроса и **passage:**
для документов, даже если текст русский. Это соответствует распределению
обучения модели: удаление префиксов может изменить качество. Mean pooling
исключает padding по attention_mask, затем выполняется L2 normalization.
Размер вектора — 1024, ES mapping хранит indexed dense_vector с cosine similarity.

BM25 использует title^2/text и русский analyzer. Его сила — точные слова,
номера и термины. Dense kNN ищет семантическую близость; num_candidates=100,
k=50 — учебные настройки. Оба поиска запускаются параллельно после embedding.
ACL public=true и фильтр vertical одинаковы в обеих ветках. Для выбранного
rail билета допустимы rail/common. Общему вопросу фильтр одной вертикали не
навязывается. Если итоговый набор содержит несколько предметных вертикалей,
orchestrator оставляет только common для общего ответа, если такие документы есть,
иначе уточняет вид транспорта вместо объединения правил.

## RRF

Для кандидата d: `RRF(d) = sum(1 / (60 + rank_i(d)))`, ранги начинаются с 1.
Число 60 сглаживает преимущество первых позиций; его тоже можно исследовать.
BM25 score и cosine не складываются: у них разные шкалы. RRF использует только
порядок, объединяя кандидатов по chunk_id. Дубликат внутри одной ветки не даёт
дополнительный голос. После fusion остаются **Top-20**.

## Reranking и gate

BGE-reranker-v2-m3 рассматривает query/document вместе и точнее оценивает
взаимодействия токенов, чем independent embeddings. Он дороже, поэтому получает
20 кандидатов, а не весь индекс. Один logit переводится sigmoid в [0,1], но это
не калиброванная вероятность релевантности. RRF score не участвует в gate.

После reranking отбрасываются значения ниже `COPILOT_RERANK_THRESHOLD` и nonfinite,
генератор получает максимум **Top-3**. Нет оставшихся — fallback. Порог 0.65 дан
лишь как пример; калибруйте по precision/recall, доле fallback, вертикали и
стоимости ложного ответа. NLI threshold=0.8 калибруется отдельно. Замена model
checkpoint, chunk size, языка или quantization требует повторной калибровки.

## Версии и Redis

Chunk IDs включают document/version/position/hash. Ingestion обновляет chunks,
удаляет старые версии, затем записывает version marker. Между этими шагами ES не
обеспечивает транзакцию: есть окно смешанной видимости. Для строгого snapshot
перестраивайте индекс и переключайте alias; текущая реализация это не симулирует.

TTL Redis ограничивает время жизни результатов. Ключ содержит cache schema v1,
версию KB и hash нормализованного публичного запроса. Только allowlist каталога
и отсутствие истории/выбора разрешают кэш. Произвольный hash не обезличивает запрос.
При обновлении знаний нужно изменить `COPILOT_KB_VERSION`; без этого stale chunks
могут жить до TTL. Ingestion не делает вид, что умеет атомарно менять env всех Pods.
В ключе production следует учитывать также embedding/reranker/prompt/filter revision.
