# Один запрос от начала до конца

1. Backend оператора аутентифицирует запрос и выбирает доверенный trip_id.
   Текст клиента не может заменить этот ID. FastAPI проверяет service token.
2. `OrderClient.get_trip` запрашивает только разрешённые поля. Неуспех ACL не
   превращается в поиск по другой поездке. Явный выбор билетов проверяется до LLM.
3. `ModelRouter` получает историю, поездку и вопрос. Qwen 1.5B возвращает JSON
   `RouteDecision`; HTTP клиент проверяет finish_reason, JSON и Pydantic схему.
4. `validate_route` проверяет ticket_ids относительно выбранной поездки и выбора
   оператора. Наличие реального ID ещё не доказывает правильность выбора:
   неоднозначный запрос о нескольких билетах должен перейти в clarify.
5. `clarify` возвращает вопрос оператору, `fallback` — ручную обработку.
   `general` ищет без обязательной вертикали, `retrieve` — с типом выбранного билета.
   Для разных выбранных вертикалей выбирается последовательный разбор через clarify.
   Если общий поиск вернул разные вертикали и common, ответ строится только по common.
6. Для точного совпадения с публичным каталогом без истории/выбора проверяется
   Redis. Кэш содержит только public chunks, не готовый персональный ответ.
7. E5 → BM25 + kNN → RRF Top20 → BGE → gate → максимум 3 chunks.
8. `DraftGenerator` через LangChain собирает промпт. Qwen 14B возвращает
   answer и claims с chunk IDs; источники передаются как недоверенные данные.
9. `DraftVerifier` сверяет answer с объединением claims, цитаты с контекстом,
   числовые атомы с evidence, даты с поездкой и NLI для каждого предложения.
   Статусы заказа всегда отклоняются в пользу оператора; вероятностная модель
   не подтверждает текущий статус заказа. NLI не является гарантией истины.
10. Ответ включает `requires_operator_approval: true`. Отправку клиенту
    реализует внешний backend только после действия человека.

Примеры:

| Вопрос / выбор | Решение |
|---|---|
| «Как вернуть билет?», rail + avia | clarify |
| «Общие правила возврата» | general, без ticket_ids |
| «Как вернуть?», оператор выбрал rail-1 | retrieve, rail + common |
| «Вернуть авиа и поезд» | clarify, разбирать по очереди |
| Уверенных документов нет | fallback |
| Несуществующий ticket_id в JSON | fallback после ошибки валидации |

Повторная отправка draft может создать другой request_id и требует повторного
инференса. Feedback идемпотентен по event_id. Kafka не участвует в draft endpoint.
Общий budget запроса ограничен asyncio.timeout, отдельные HTTP вызовы — HTTPX timeout.
Отказ Redis не блокирует retrieval; отказ модели/ES не выдаётся за успешный ответ.
